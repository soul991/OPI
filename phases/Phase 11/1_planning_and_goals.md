## 6. Workstream D - Live research-agent proof (D-026) - uses OpenRouter (free tier)
- Provider: **OpenRouter**. **Cloud-first:** the scheduled research must run in GitHub Actions and must not depend on the user's computer being on. The user stores the key once as a GitHub repository secret named `OPENROUTER_API_KEY` (Settings > Secrets and variables > Actions); the workflow passes it as `env: OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}`. A local key is optional and only for manual testing. Never commit the key, print it, or write it into logs, run files or snapshots. Gemini stays optional behind the same interface.
- **Scheduled cloud job (`.github/workflows/daily.yml`, extend it):** discover upcoming/open IPOs -> after bidding closes, research agent collects inputs -> code grounds each value in saved snapshots -> score -> append to the prediction log -> after listing, record the official actual -> regenerate the dashboard -> bot commit. Idempotent (re-running adds no duplicate rows), `concurrency` group so two runs never overlap, and `permissions: contents: write` only.
- **Cloud evidence required for D-026 FIXED:** a green scheduled (`event: schedule`, not manual) Actions run whose log shows provider, model id, request count and grounding rate, and whose bot commit contains the snapshots. The key must not appear in the log (`gh run view --log | grep sk-or-` empty).
- **Known cloud risks to test and report, not assume away:** (1) exchange or tracker sites may block GitHub runner IPs, so record per source whether the runner could fetch it; a blocked source must produce a logged `SKIPPED_BLOCKED_SOURCE`, never a guessed value; (2) GitHub cron can start late, so the job runs several times per day and scoring uses the close time, not the run time; (3) GitHub can pause scheduled workflows after 60 days without repo activity, so add a check in `verify_all.py` that the last scheduled run is under 36 hours old; (4) free OpenRouter limits (below) are shared by all runs of the key.
- Endpoint: `https://openrouter.ai/api/v1/chat/completions` (OpenAI-style). Keep the model list in `config/research_models.json`, not in code. Initial order (verified working or listed free on 2026-10-24): `nvidia/nemotron-3.5-super-vl:free` (tested OK), `google/gemma-4-31b-it:free`, `nvidia/nemotron-3-super-120b-a12b:free`.
- Free-tier limits: 20 requests/minute, 50 requests/day (1,000/day after about 10 credits are bought). The agent must count requests, sleep on HTTP 429, and on HTTP 404 ("no endpoints") move to the next model in the list. Before each run it refreshes the free list from `https://openrouter.ai/api/v1/models` (public) and drops ids that are no longer `:free`.
- If the key or web access is missing, stop this workstream, mark D-026 `NOT FIXED (needs user action)` and continue with the others. Do not use mock data in `data/research_runs` or `data/evidence`.
- Let the cloud job run the agent on the next 2 to 3 genuinely upcoming IPOs. Required evidence per run: provider and exact model id, real URLs, code-saved snapshots, per-field grounding rate, request count, and each value matched against the saved snapshot by code. Fields not found in a snapshot are `UNGROUNDED` and excluded from scoring.
- Model comparison (measured, not claimed): run the same IPOs through each of the 3 listed models and report grounding rate and field-level differences against the built-in `opi.ingest` inputs. No "best model" wording unless a paired comparison supports it; with 2 to 3 IPOs, report descriptively.
- Tests: key never appears in any committed file (`git grep` for `sk-or-` returns nothing); a mocked 404 falls through to the next model; a mocked 429 sleeps and retries; ungrounded fields are dropped.
